P3 — Você aperta "parar" e o sistema age mesmo assim

O gate pergunta à Issue. Quem perde autoridade é o Run. São dois objetos, e um não responde pelo outro.

Tipo Fatia Slot 2 de 2 Portas :18082 / :15433 Branch posse/fatia2-run-com-autoridade Kickoff já escrito

O defeito

Você aperta "parar". O CAS RUNNING→INTERRUPTED vence. O kill é best-effort e não pega. O processo segue vivo. E os 4 gates de saída disparam em nome de um run cuja autoridade foi revogada — criando Approval, issue dirigida, parecer e pedido de skill.

Por que a fatia anterior não cobriu isto

Esse cenário não passa por checkout nenhum. A Fatia I-ter amarrou identidade; esta é o eixo liveness. Medido pela conferência: a I-ter reforçou o caso desta fatia em vez de erodi-lo. Complementares, sem dupla contagem.

B — O D1 embutido: a entrega descartada

Decisão do dono: é a mesma corrida vista de dois lados. A Fatia II impede que os gates do run parado ajam; o D1 é a entrega do run parado sendo descartada. Mesmo método, mesmo arquivo, mesmo tick.

Não tente recuperar o trabalho

/reabrir é board-only com guard status='DONE' e nem alcança Issue BLOCKED. Ressurreição automática invade assunto de outra fatia. O entregável é tornar a perda AUDÍVEL — e o guard no mecanismo cobre os irmãos de graça.

Três correções da conferência — não as reproduza erradas

A correção
🔴 "É o único resíduo que perde trabalho" é FALSO. O descarte é propriedade do MECANISMO (o retorno jogado fora), não do gatilho. Irmãos medidos: (i) o destrave manual da ficha sobre uma Issue cujo run ainda executa; (ii) o posseConfirmada fail-soft — num erro transitório de banco ele devolve false, os 4 gates são pulados, e se o soluço passa o settle sucede: a Issue fecha sem o Approval/dirigir/parecer que o run produziu. Porta possivelmente mais larga que a do próprio D1. ⇒ D1 é a instância mais afiada de uma CLASSE.
🟠 São QUATRO destinos, não três. Falta o caso em que o kill falha, o run termina com sucesso e o reaper ainda não rodou (Δ<5 s): tryComplete casa 1 linha, a Issue vai a DONE e o Run fica INTERRUPTED para sempre. O "parar" do operador é atropelado e uma entrega entra no board a partir de um run que ele mandou matar. Não está nomeado em lugar nenhum.
🔵 "Em silêncio" é exagero leve: o posseConfirmada grava GATE_DE_SAIDA_SEM_POSSE no StepTrace antes. Há migalha — mas enquadrada como "os 4 gates foram descartados", não "uma entrega foi descartada", e nada a correlaciona com a Issue. Não herde o exagero no texto do conserto.
🔵 A janela não é "5 s de exposição": é "5 s de carência, depois perda CERTA" — condicionado ao kill falhar, o reaper ganha quase sempre. E a exposição CRESCEU: foi a I-bis que pôs INTERRUPTED no reaper. Custo criado por uma fatia, nomeado por outra, consertado por esta.
