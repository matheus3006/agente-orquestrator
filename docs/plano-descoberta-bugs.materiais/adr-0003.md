**Achado de fronteira (relevante à A7/A8 e ao roteiro da A9)** — `AdapterRunExecutor:446` gateia o
pedido-skill em `result.succeeded()`, que é **TRUE para `Result.okNoop`**: um run no-op sobre Issue
AINDA chama `skillRequestGate.handle(...)`, com texto vazio. É o único ponto pós-#34 em que o no-op
atravessa um `succeeded()` sem a guarda `!noop` (o gate do preview usa o `outcome` — `RunOutcome.noop`
tem `succeeded=false`, já protegido). Inócuo hoje (texto vazio ⟹ o scanner não acha bloco), mas o
roteiro não deve ler "o gate rodou" como "o motor rodou".

**Achado de fronteira (roteiro de QUALQUER afirmação que dependa de agente contratado pelo gate)** —
`Agent.adapterType` tem default **`"process"`** (`Agent.java:36`) e o gate contrata com
`runtimeCommand=null` (`ApprovalService:345-352`). Pós-#34 um hire cujo alvo NÃO traz `adapterType`
segue MUDO — só que agora falha honesto (no-op → run FAILED → issue BLOCKED) em vez do DONE fantasma.
Para a bateria colher executor que trabalha, a proposta do CEO (ou o override do dono no menu de
approve, que vence campo-a-campo) tem de carregar motor RICO (claude/codex).
