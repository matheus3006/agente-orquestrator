**Achado de fronteira (A20 — a efemeridade é imposta pelo CHECKOUT, não pelo `resolveForRun`):**
`SkillSetService:157-160` exclui os anexos quando a Issue está fechada, mas `tryCheckout`
(`IssueRepository:81`) já recusa QUALQUER run sobre Issue fora de `('OPEN','IN_PROGRESS')` — logo
nenhum run chega a EXECUTAR sobre Issue fechada e o galho de Issue fechada do `resolveForRun` é
defensivo. Ele só é alcançado porque a materialização roda ANTES do checkout
(`AdapterRunExecutor:166-179` vs `:211`): o run materializa o workspace (sem o anexo) e só então morre
no checkout. É por isso que o observável da A20 é o **workspace**, não um run concluído. Dois
subprodutos para o roadmap:
- O cenário "REOPEN→re-run" que a passada anterior sugeria estava ERRADO — reabrir devolve a Issue a
  OPEN e os anexos voltam a entrar; ele testa o contrário do que a A20 afirma.
- A mensagem de falha do checkout é enganosa: `AdapterRunExecutor:213` diz "checkout da issue falhou
  (ja em execucao por outro run)" TAMBÉM quando a causa real é Issue fechada (DONE/CANCELLED) —
  diagnóstico errado no erro do run. Candidato a item do roadmap de ajustes (⚪/🟡).
