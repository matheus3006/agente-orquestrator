Nota: as 3 provas do trilho lease-lost (A11/A12/A14) valem como PROVADA pelo contrato da fase, mas TODAS vieram de produtor desviado (UPDATE manual no pg da descartável, lease-renew-ms=3000); a própria ADR (:47) nomeia os dois produtores reais nunca pisados — "reaper requeou + outro claim levou" e "hard-stop cancelou em voo" (ADR-0040) — o hard-stop é exercitável HOJE pelo kill de run de turno na UI. O item 21 do dossiê (sonda pré-fix) mostrou que o double-work do mesmo run é alcançável quando o reaper interleava com worker vivo; o LeaseRenewer estreita a janela (4+ pulsos perdidos) mas não a zera — território de A2/A7/A8, hoje coberto só por unit+sonda. O item 20 [REAL] (0 runs com attempt>1 na história inteira) é evidência de que o caminho reaper→requeue NUNCA rodou em produção — A7 é caminho virgem de verdade.

Nota do verificador (2026-07-16): (i) cheque de "fatia posterior tocou o mecanismo" feito por git — `LeaseRenewer` e `HeartbeatDispatcher` intocados desde a própria fatia da renovação (e88258e, 2026-07-10), logo as provas dos itens 33/79 seguem cobrindo A6/A13/A14 sem rebaixamento; `HeartbeatRunStore` FOI tocado depois, mas 57bf8a3 (2026-07-12, interrupt ADR-0040) só ADICIONA o método `interrupt` como caller novo do MESMO guard do `finalizeRun` (renewLease/finalize inalterados) e f85a876 (2026-07-14, breaker R18-B) mexe no `promoteIfNeeded` — mecanismo do A5, cuja evidência (item 13) é o /verify PÓS-toque, portanto válida.
