## Reclassificação 2026-07-17 (R22-B — pós-merge do PR #34, contra main 4c1b35f)

- **0017-A14** · ⛔ BUG#1 → 🎯 AGORA (pós-reboot) · O reboot destrava a OBSERVAÇÃO, não a afirmação. O arquiteto passa a rodar a issue de planejamento com motor — mas **não existe canal para um run de issue criar issue**: `ProposalScanner` só é chamado do `ConversationTurnCoordinator:156,169` (galho TURNO); do run de issue sai apenas `SKILL_INSTALL_REQUEST` (`AdapterRunExecutor:446-449`). Toda Issue viva nasce do dono (`NewIssueDialog`) ou do CEO-em-turno (`CREATE_ISSUE`, `ApprovalService:355-370`). A bateria pós-reboot deve CONFIRMAR a ausência — expectativa de REFUTAÇÃO da letra ":52-53 a autoria já garante a ordem".
- Achado de fronteira para o montador: é o **gêmeo espelhado** de 0018-A35 ("o executor nasce sem mãos"). A mesma ausência de canal que REFUTA "o arquiteto é a FONTE das tasks" é a que faz "o executor não muta estrutura" PASSAR — arquiteto e executor têm exatamente as mesmas (zero) mãos, e a ADR-0017 pede que o arquiteto tenha uma a mais.
